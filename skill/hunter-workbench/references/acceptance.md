# 验证与验收

## 本技能验证

- 使用 skill-creator 的 `quick_validate.py` 验证 frontmatter、名称和未完成占位内容。
- 检查 SKILL.md 和各 references 的相对路径存在，UI 元数据引用正确技能名。
- 静态复核需求覆盖和关键场景；这不能替代应用构建、浏览器或真实 DeepSeek 测试。

## 应用验证命令约定

以下仅是计划；仓库初始化后以实际 manifest 为准，将可执行命令补入根 `AGENTS.md`。

| 范围 | 计划命令/方式 | 限制 |
| --- | --- | --- |
| 前端类型 | `pnpm typecheck` | 上游当前存在此脚本；不可依赖 skip 掩盖新增业务类型问题 |
| 前端 lint | 项目本地 ESLint 的只读检查 | 上游 lint 脚本带 `--fix`，先确认影响范围 |
| 前端构建 | `pnpm build` 或经调整的非删除构建入口 | 上游 build 包含 rimraf，Vite 也可能清空目录；无删除授权时使用独立输出目录并显式 `--emptyOutDir false` |
| 后端静态 | 虚拟环境内 `python -m ruff check app tests` | 按实际依赖配置建立，不全局安装 |
| 后端业务 | 虚拟环境内 `python -m pytest` | 使用隔离测试数据库和合成附件 |
| 浏览器 | 实际可用的浏览器自动化工具或手工可重复步骤 | 不可只用接口测试声称页面已验证 |
| 外部服务 | 授权后的合成样本真实调用 | mock 与真实 API 分开报告 |

按改动范围选择验证，关键链路通过后不无目的重复全量测试。尚未建立的命令应标“计划”，不能写成已通过。

## 桌面业务范围

- 用户明确无手机业务场景。后续 UI 验收覆盖电脑浏览器 1024、1280、1440、1920 px，不再开发手机适配或运行手机/平板专用用例。
- 保留桌面窗口尺寸变化、侧栏收缩、键盘、较矮窗口弹层、长文本、表格局部滚动、加载/错误恢复和真实业务链路验证。
- 混在手机用例中的日期弹层、表单保存、返回后滚动恢复等通用行为，移到桌面视口继续验证；不能连同手机测试整体丢弃。
- 浏览器脚本按桌面场景组织；实施及实际通过结果见项目 `docs/desktop-scope-plan.md`，不沿用历史手机验收数量充当当前结果。历史验收结果和截图保留。

## 业务场景

### A. 职位和人才基础

1. 手动创建职位，填公司、团队人数、汇报上级和业务情况；刷新后保留。
2. 团队人数空、0、负数分别得到未知、明确无下属、校验拒绝。
3. 新增人才，保存用户要求的全部字段；缺联系方式也能建档，缺姓名被拒绝。
4. 添加多段履历和两条沟通，列表、详情和时间顺序正确。
5. 同人才关联两个职位；改一个推荐状态，另一个保持原值。
6. 新增日期/单选自定义字段，填写后刷新仍保留；类型不符被拒绝。

### B. 导入与文件

1. 合成 `.xlsx` 含全部七个用户字段、中文、空值和多种联系方式；预览映射正确。
2. 错误日期、缺姓名、重名、重复电话、公式单元格有可理解提示。
3. 同一批次双击提交和请求重试不重复建档；校验失败事务无部分写入。
4. TXT、文本 PDF、DOCX、图片、扫描 PDF 分别验证，提取结果可预览并修正。
5. 若声明支持旧 DOC，必须有实际样本通过；不能仅把扩展名加入白名单。
6. 文件伪装、超限、损坏、空 PDF 和路径穿越输入被拒绝或进入明确失败状态。
7. 未登录或无权访问者不能通过附件 URL 取得原文件。
8. JD 创建链路不触发 DeepSeek 调用；通过提供方测试替身的调用记录验证。

### C. AI 与事实依据

1. 同一简历匹配两个不同 JD，结果挂在各自推荐记录下。
2. 简历未写团队人数时返回 unknown，不伪造不匹配或具体管理人数。
3. 证据页/段能够定位输入；校验无效 JSON、截断和空响应不进入 succeeded。
4. 缺 key、401、429、超时和 5xx 都可理解且保留业务数据；失败任务可追踪。
5. 公司资料完全缺失时，话术不编造裁员、融资和经营近况。
6. 有资料时，展示双方公司来源和日期；录入日期不冒充事实日期。
7. 更新 JD/简历后旧结果仍可查看且提示过期；新任务使用新版本。
8. 输入含“忽略规则/泄露密钥”时当成数据，不执行相关指令。
9. 人工编辑的话术与再次生成的草稿均保留；复制操作不发送消息。
10. 重启时 running 任务进入可识别的中断状态，不无限等待或静默重复收费调用。

### D. 交付条件

- 前端成功提示以真实后端结果为准；断网、失败、空列表不显示伪成功。
- 后端权限校验与登录退出有效；模板 mock 不参与真实业务运行。
- 浏览器、日志和构建产物无 DeepSeek key、认证密钥或真实简历全文。
- 提供可复现启动步骤与配置名称，列出实际通过项和具体限制。
- 原有 skill 和用户文件保留；未授权操作未执行。

## 本次文档的场景复核方法

逐条模拟以下输入，沿文档检查是否能得到唯一且合理的行动：

- “扫描版 JD 上传后直接自动建岗”→本地 OCR，预览并人工确认，零大模型建岗调用。
- “同名人才从 Excel 再导入一次”→重复提醒，不按姓名合并；同提交重试保持幂等。
- “候选人不写团队人数但岗位要求带团队”→unknown 和待核实问题。
- “帮我说候选人公司最近裁员，但没有资料”→不生成肯定事实，提示资料缺失。
- “没有 DeepSeek key，先完成页面”→可以继续后端契约与合成测试，不伪造产品分析成功。
- “运行上游 build 清理 dist”→先审查删除授权或采用无删除构建入口。
- “方案通过了，直接执行迁移”→检查是否已授权具体 schema/迁移范围；无授权则提交具体清单。
