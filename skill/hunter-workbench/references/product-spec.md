# 业务规格

## 需求状态

用户明确要求：

1. 根据文本、TXT、PDF、Word、图片中的 JD 创建职位，此过程不需要 AI 服务。
2. 导入候选人简历，使用 DeepSeek API 分析与目标岗位的匹配度。
3. 结合候选人任职公司、职位、工作经历、目标岗位和双方公司现状，用 DeepSeek 生成沟通话术。
4. 人才库包含建联日期、姓名、公司、职位、联系方式、沟通记录、简历来源，支持后期维护和 Excel 上传。
5. 职位包含公司、职位、下属团队人数、汇报上级、业务具体情况。
6. 前端采用 Pure Admin；先生成详细 skill，再执行。
7. 工作台只用于电脑浏览器，无手机业务场景；后续不要求手机端适配与手机端测试。

以下为可调整的设计默认值，不视为用户已逐项确认：先服务个人/小团队、中文界面、手动维护公司资料、不接招聘平台、不自动发送沟通内容。电脑浏览器是用户明确的使用范围。首次交付覆盖全部明确需求，可分阶段验收。

## 页面与主要操作

| 页面 | 主要内容 | 核心操作 |
| --- | --- | --- |
| 工作台 | 在招岗位、待跟进推荐、最近更新 | 从真实数据进入详情，不堆无业务意义图表 |
| 人才库 | 建联日期、姓名、当前公司、当前职位、联系方式、来源 | 搜索、筛选、新建、编辑、导入、查看详情 |
| 人才详情 | 基本信息、任职经历、简历版本、沟通时间线、关联岗位 | 编辑、上传简历、追加沟通、关联职位 |
| 职位库 | 公司、职位名称、招聘状态、更新时间 | 新建、上传 JD、筛选、查看推荐名单 |
| 职位详情 | JD、团队人数、汇报上级、业务情况、候选人列表 | 编辑、关联人才、分析匹配、生成话术 |
| 公司资料 | 公司基本信息、带来源的业务近况 | 维护资料、查看日期、关联岗位和任职经历 |
| 导入与分析任务 | 导入批次、解析进度、分析状态、错误 | 查看结果、重试失败项、回到相关业务记录 |
| 设置 | 数据字典、有限类型的自定义字段、服务连接状态 | 维护选项和字段；API key 不在浏览器表单中回显 |

列表提供空状态、加载中、失败重试；表单失败保留输入。按钮与字段使用中文业务用语，避免把数据库表名和模型参数呈现给日常使用者。

## 实体与字段

### 人才 Candidate

- `id`：稳定业务标识。
- `contacted_on`：建联日期，可空；未知不能自动填成今天。
- `name`：姓名，必填；允许重名。
- `current_company_id`、`current_company_name`：优先引用公司资料，尚未建档的公司也可保留文本。
- `current_title`：当前职位，可空。
- `contact_methods`：带类型的多个联系方式；电话、微信、邮箱等，允许缺失。
- `resume_source`：简历来源，可维护选项与补充说明。
- `custom_fields`：按字段定义校验的附加值。
- 创建与更新时间由系统记录，与建联日期区分。

### 任职经历 Employment

- 人才、公司引用/原始公司名、职位、起止年月、是否在职、职责与业绩。
- 同一人可有多段、交叠或日期未知的经历；不强行猜测精确到日。
- 提取内容先作为草稿，用户确认后才覆盖已核实的结构化履历。

### 公司 Company 与资料 CompanyFact

- 公司名、别名、行业、业务简介。
- 公司资料单独记录内容、来源类型、来源链接/用户说明、资料日期、采集时间。
- 区分资料发生/发布日期和录入日期；未知日期保持未知。
- 原始资料与 AI 概括分开，不把生成结论写回成事实。

### 职位 Job

- `company_id`、`title`：必填。
- `team_size`：下属团队人数，非负整数或未知；0 表示明确没有，空表示未知。
- `reports_to`：汇报上级，先存职位/称谓文本，无需录入实际姓名。
- `business_context`：业务具体情况。
- `jd_text`、JD 文件引用及来源；提取文本与用户编辑版本可区分。
- `requirements`：人工确认的硬性要求与加分项，用于解释匹配依据。
- `status`：建议为草稿/招聘中/暂停/关闭，可后续调整。
- 薪资、城市等属于可选扩展，未提供时不补造。

### 推荐 Application

- `candidate_id` + `job_id` 唯一；重复关联返回已有记录。
- 建议状态：待评估/待建联/沟通中/已推荐/面试中/Offer/入职/暂不推进。
- 这套状态须让用户可调整；不引入自动发送或自动淘汰。
- 不同推荐拥有独立状态、匹配历史和话术历史。

### 沟通记录 Communication

- 人才必填；可关联一个具体推荐。
- 沟通时间、渠道、内容、结果、下一步及可选跟进日期。
- 按记录追加；编辑保留更新时间，不能用一个备注字段覆盖所有历史。
- 录入是记录行为，不触发实际外发。

### 文件、导入、AI 任务

- FileAsset：原名、检测类型、大小、校验和、相对存储标识、归属和解析状态。
- ResumeVersion：人才、文件/文本、提取结果、版本、用户确认状态。
- ImportBatch/ImportRow：字段映射、行号、预览、错误、提交状态与结果。
- AnalysisRun：推荐、输入快照、模型与提示词版本、状态、结构化结果、错误和时间。
- OutreachDraft：推荐、输入快照、生成/编辑内容、事实来源和版本；生成内容允许人工修改。

## 自定义字段与数据维护

- 用户希望后期维护和添加字段。建议首版支持文本、数字、日期、单选四类，适用于人才和职位。
- 字段定义包含稳定 `key`、中文名称、实体类型、值类型、选项、是否必填/启用。
- 用预先设计的附加字段存储实现日常新增字段；不让每次点击“添加字段”都执行数据库 ALTER TABLE。
- 已使用字段的类型变更要说明兼容方式；不自动清空历史值。
- 第一版提供编辑和状态归档；物理删除、批量覆盖和合并另行授权。

## 业务不变量

- 简历更新、JD 修改、公司资料变化之后，旧分析保留，并显示输入可能过期。
- 分析失败不影响人才、职位、附件和沟通记录使用。
- 姓名重复允许创建；联系方式重复展示提醒，不静默合并。
- 同公司多个职位、同人才多个推荐均是正常情况。
- 日期按 Asia/Shanghai 展示；日期字段与时间戳分别处理，时间戳以 UTC 存储。
