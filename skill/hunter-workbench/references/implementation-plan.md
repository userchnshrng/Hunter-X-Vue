# 实施计划与待确认范围

状态：整体实施计划已确认；阶段 A、UI 和阶段 B 已完成验收。阶段 B 的具体授权见项目 `docs/stage-b-plan.md`，实际结果见 `docs/stage-b-validation.md`；C–E 尚未推进。

## 拟定交付

基于 Pure Admin 精简版构建中文猎头工作台，配 FastAPI、PostgreSQL 和私有附件存储，覆盖已明确的职位、人才库、Excel、简历、DeepSeek 匹配和话术需求。

默认以个人/小团队使用为起点；公司近况由用户维护，首版不增加自动联网采集，不自动发消息。

## 阶段 A：工程底座和真实数据基础

1. 检查现有 Node/Python/PostgreSQL/包管理器和浏览器能力，不全局安装。
2. 选定 Pure Admin thin 的具体 commit，记录来源/许可证；先审查配置、安装脚本和构建中的删除动作。
3. 创建 frontend/backend 结构，建立真实后端健康检查和统一错误处理。
4. 提交初始概念 schema、迁移范围、配置文件改动清单与验证命令；有授权后才创建/执行对应内容。
5. 接通真实登录、公司、职位、人才、经历、沟通和推荐存储，不保留生产假登录。

阶段结果：刷新网页后数据仍存在；人才与多个岗位的状态独立；登录和文件访问规则可验证。

## 阶段 B：日常维护、Excel、自定义字段

1. 完成人才/职位列表筛选和详情编辑，以及建议字段的显示和校验。
2. 支持文本、数字、日期和单选的自定义字段，新增字段不改物理 schema。
3. 实现 Excel/CSV 映射、错误预览、重复提醒、确认提交及幂等。
4. 录入公司资料和来源日期，沟通记录按时间呈现。

阶段结果：合成 Excel 的正确行全部入库，错误行能定位；重试不会生成重复人才；自定义字段可维护。

## 阶段 C：JD 和简历文件

1. 支持粘贴文本、TXT、文本 PDF、DOCX 上传和提取预览。
2. 选定并验证本地中文 OCR，覆盖图片和扫描 PDF；以项目依赖或经授权的工具运行。
3. 验证旧 DOC 转换路径；若运行环境缺少转换器，明确列为未完成能力而非声称支持。
4. 解析结果人工确认再入库；简历保留版本，JD 建岗不调用大模型。

阶段结果：每类承诺格式都用合成样本实际验证；原件私有；解析失败可改用手动粘贴并保留失败原因。

## 阶段 D：DeepSeek 匹配与话术

1. 实现持久化任务、输入快照、结构化结果、错误状态与有限重试。
2. 匹配围绕岗位要求、履历证据和未知项；不同推荐的结果隔离。
3. 话术引用双方公司资料；缺少资料时明确显示限制。
4. 合成数据验证成功、超时、限流、无效 JSON 等路径。
5. 用户授权并完成服务配置后做真实 API 联调，记录实际结果与未验证范围。

阶段结果：可查看匹配依据、编辑和复制话术、保留历史；不会自动对外发送。

## 阶段 E：整体验收与使用交付

1. 按 acceptance.md 跑前后端和浏览器关键路径。
2. 校验重启持久化、旧分析过期提示、私有附件和任务中断处理。
3. 写准确的本地启动、配置、备份/恢复说明。恢复演练只在隔离测试库进行。
4. 向用户展示使用流程、实际验证证据、需要人工处理的格式限制。
5. 部署与公开发布属于另行授权动作；本地开发完成不自动执行生产部署。

## 当前可审阅的选择

| 项目 | 默认方案 | 替代方案或影响 |
| --- | --- | --- |
| 前端 | Pure Admin 非国际化精简版 | 用户已选择 Pure Admin，不再重新选型 |
| 数据库 | 已授权先用 SQLite 本地开发，部署 PostgreSQL | 部署前另行验证 PostgreSQL；SQLite 验收不代表 PostgreSQL 已验证 |
| 公司现状来源 | 用户提供且附日期/来源 | 自动检索需要追加信息源、时效和检索费用设计 |
| 附件 | 私有本地目录 | 上线多实例前改对象存储，需要迁移方案 |
| 用户范围 | 个人/小团队 | 部门隔离、候选人归属、外部客户访问另作需求确认 |
| OCR/旧 DOC | 本地工具，实际验证后声明支持 | 工具缺失先说明限制，但不跳过完整交付所需能力 |

- 只读检查、文档修订、合成样本设计可继续。已经确认过的具体动作不重复请求。
- 不承诺未经实测的工期、服务器成本或文件识别准确率。
