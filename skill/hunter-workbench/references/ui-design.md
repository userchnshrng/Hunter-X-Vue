# UI 视觉规范

## 适用与来源

用于 Hunter-X-Vue 现有 Pure Admin 工作台的 UI 改造，以及后续业务页面沿用同一风格。

- 风格参考为用户提供的仪表盘截图，项目副本：[参考图](../../../docs/assets/ui-style-reference.png)。
- 参考其蓝紫色、浅灰紫画布、白色大圆角卡片、细线图标和疏密关系；业务内容使用猎头工作台现有信息。
- 不引入图中的 DealDeck 品牌、销售统计、付费升级宣传和虚构增长率。
- UI 方案已获用户确认并完成实现；正式范围见 [UI 改造计划](../../../docs/ui-redesign-plan.md)，实际验收见 [UI 验收记录](../../../docs/ui-validation.md)。

## 视觉起始值

以下是拟定设计值，不是从图片精确取样的结果。实施时结合中文内容和实际截图校准。

| 用途 | 初始设计值 |
| --- | --- |
| 外层画布 | `#D5D7E2` |
| 工作台底色 | `#F1F0FA` |
| 卡片 | `#FFFFFF` |
| 侧栏 | `#FAFAFE` |
| 主色 | `#4F46F5` |
| 主色悬停 | `#4338CA` |
| 正文 | `#202234` |
| 次要文字 | `#65687E` |
| 细边框 | `#E7E7F2` |
| 成功 | 深绿文字配浅绿底，不能只靠颜色表达状态 |
| 错误 | 深红文字配浅红底，附明确错误内容 |
| 外框/卡片/控件圆角 | 24 / 20 / 10–12 px |
| 主要间距 | 8 / 12 / 16 / 24 / 32 px |

常规中文内容优先 14 px，表单与交互文字不为追求截图比例缩到 10–11 px。大标题约 26–30 px，关键数字约 30–36 px，注释约 12 px。使用现有系统无衬线字体，不为本次改造下载商业字体。

阴影轻、边框弱；蓝紫色集中在主要操作、选中导航和一张重点统计卡片。其余卡片维持白底，避免到处使用渐变和大面积高饱和色。

## 应用外壳

- 桌面采用有外边距的圆角容器，顶部与侧栏属于同一个工作台，内容可独立滚动。
- 保留 Pure Admin 菜单与导航组件，使用 `.hunter-shell` 下的布局适配；不重建路由、登录或权限。
- 当前布局依赖 viewport 固定定位和偏移计算。正式改造优先用容器布局与 sticky，在这一模式替换相关固定偏移，避免通过 scale 或大量 `!important` 叠出浮动外框。
- 外框样式不能通过祖先 `transform` 造成 fixed 菜单、弹窗或抽屉定位异常。Element Plus 弹层继续 teleport 到合适容器，检查层级与焦点。
- 导航简化为品牌、页面上下文、必要工具和账号菜单；默认隐藏重复标签行，保留路由与页面访问能力。
- 默认使用浅色纵向布局，新导航不暴露尚未适配的多布局/主题设置入口；原模板设置文件保留。收缩侧栏、手机菜单和退出登录继续可用。
- 当前项目的绿色主题偏好可能存于本地缓存。实施时为新主题做明确版本迁移，只调整相关显示偏好，禁止 `localStorage.clear()`，不触碰登录凭据或业务数据。

## 页面组合

### 工作台

- 顶部：清晰的工作台标题、简短说明和刷新操作。
- 统计：人才总数、在招职位、合作公司、职位推荐四张卡片，第一张用蓝紫重点样式。
- 主区：最近更新的人才列表；辅助区：当前在招职位与已有业务入口。
- 数据只来自现有 `/dashboard`、`/candidates`、`/jobs` API。列表按现有更新时间排序时明确写“最近更新”，不写“最近新增”。
- 后续拥有合适统计数据时再引入趋势/分布图；当前不为仿图伪造月份、百分比、环图比例和增长率，不为视觉效果增加后端接口。
- 空数据时显示明确空状态与可用操作，不用演示数据填充真实页面。

### 列表、详情和编辑

- 人才/职位/公司列表以大圆角白色容器承载工具栏、表格和分页，保留姓名/职位链接、状态与主要操作。
- 表格维持可读密度：正常行高约 52–60 px，长文本省略并可进入详情或查看提示；联系方式与姓名不挤压成不可辨识文本。
- 详情采用信息卡片与时间线，保持履历、推荐和沟通的现有语义。
- 表单、按钮、日期控件、下拉、分页、弹窗、抽屉、提示和 loading 使用同一主题变量。
- 登录页沿用蓝紫与浅灰紫风格，保留真实登录与首次管理员创建说明。
- 当前已暴露的所有操作保持可用；UI 改造不增加 Excel、OCR、AI 等尚未实现的功能入口。

## 自适应

| 容器范围 | 布局 |
| --- | --- |
| 大于 990 px | 展开侧栏；四张统计卡；主辅内容区；外框留白 |
| 761–990 px | 收缩侧栏；统计卡按可用宽度改两列；主辅内容逐步纵向排列 |
| 不大于 760 px | 菜单抽屉；去掉装饰外边距；单列内容和表单；按钮按需换行 |

- 断点沿用现有侧栏 760/990 px 的实际宽度判断，使用可用容器宽度，而不是只按设备名称。
- 在 1440、1280、1024、768、390 和 360 px 视口检查，尤其观察外框减去边距后是否提前触发侧栏收缩。
- 窄屏保留可操作表格，必要时仅表格局部横向滚动；页面整体不能横向溢出。优先保证姓名、主要状态和详情入口可见。
- 小屏弹窗与抽屉限制宽高，内容和底部操作均可到达；输入字号至少 16 px，主要触控目标约 44 px。
- 浏览器允许用户缩放；检查现有 viewport 的 `user-scalable` 限制并调整。

## 可读性、交互与验证

- 检查常规文字约 4.5:1、较大文字约 3:1 的对比度目标；小灰字和白字紫底需实际测量，不能只依赖颜色看起来接近截图。
- 显式保留键盘焦点，菜单收缩/抽屉关闭后焦点回到触发器；支持 `prefers-reduced-motion`。
- loading 结束、页面过渡完成后截图。不要把遮罩或过渡中的淡色页面当作最终设计。
- 对列表空态、长中文、重复姓名、多联系方式、错误提示、加载中和弹窗分别检查；样本只进入隔离测试库。
- 前端类型、lint、无删除构建和现有 9 项浏览器关键流程均须通过；新增布局交互和多宽度截图见正式计划。
