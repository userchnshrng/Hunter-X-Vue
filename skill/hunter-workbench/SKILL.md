# 猎头工作台开发技能

## 目标与当前状态

为盘晋实现中文内部工作台：创建职位、维护人才库、导入 Excel 和简历、用 DeepSeek 分析岗位匹配并生成沟通话术。

- 已确认：采用 Pure Admin 方案，先完成本技能，再进入实施。
- 实施计划已获用户确认；阶段 A 已完成，验证见项目 `docs/stage-a-validation.md`。阶段 B–E 尚未实现，新增敏感操作仍按项目红线处理。
- 当前用户暂不进入 B–E；参考图风格 UI 改造已实现并通过隔离验收，见项目 `docs/ui-redesign-plan.md` 和 `docs/ui-validation.md`。后续业务页面沿用 UI 视觉规范。
- 设计默认值见引用文档，不能把建议写成用户已确认的业务事实。
- 本技能是项目内文件。当前路径不代表已安装到 Codex 的全局技能目录，也不保证自动发现；可通过文件路径明确引用。

## 必须保持的业务规则

- JD 建岗不调用大模型服务。文件提取后让用户核对岗位字段；OCR 与语义字段抽取是不同步骤。
- 人才与职位通过独立推荐记录关联。同一个人推荐给两个职位，不能共享同一条状态、匹配结果或话术记录。
- 当前公司/职位用于列表展示，历史任职经历单独保留；沟通记录逐条追加。
- 匹配结果包含依据、缺口和待核实项。未知信息不可视为不符合；分数不等于录用概率。
- 候选人所在公司和目标公司的现状必须有来源与资料日期。缺资料时明确说明，禁止根据模型记忆编造近况。
- DeepSeek 只由服务端调用。前端、构建配置和浏览器存储不接触 API key。
- 导入先提取/映射/预览，再由用户提交。相同姓名不足以自动合并人才。
- 不自动联系候选人、发消息或发邮件；话术生成和复制不等于发送授权。

## 实施方法

- 沿用 Pure Admin 的页面框架、Element Plus、路由模块和请求封装；只在适配边界修改模板公共部分。
- 先跑通公司、职位、人才和沟通的真实存储链路，再做文件导入和 AI。演示数据必须标识，不能冒充已接通后端。
- 业务模块保持独立，但第一版使用一个后端服务；没有实测需要时不引入微服务、向量库或消息队列。
- 每阶段交付可运行结果及对应验证；不要在所有页面完成前积累无法验证的代码。
- 上游版本、API 参数和可用模型需在实施时重新核实，保留所用上游 commit、许可证和本地适配说明。

## 授权与停止条件

- 遵守根 `AGENTS.md` 的删除、配置/凭据、数据库 schema/迁移、Git、全局安装及公开发布红线。
- 当前实施计划已确认，不重复询问整体方案；数据库与配置的具体授权记录见项目文档和会话。已确认的相同动作不重复询问。
- 缺少 API key 时继续实现接口、失败状态与合成数据测试，明确真实调用未验证；不要求用户把 key 发到聊天。
- 有用的独立工作可以继续，不因某个格式解析器或浏览器工具缺失而把整个阶段标成完成或阻塞。

## 交付与复核

- 使用 [验收标准](references/acceptance.md) 中与变更有关的检查；不得用 `skip`、忽略异常或虚构响应替代验证。
- 对新功能说明用户可观察到的行为、实际通过的命令和剩余限制。
- 更新实施阶段状态时只记录已发生的结果；方案、脚手架、mock 测试、真实 API 和真实业务验收分开陈述。
