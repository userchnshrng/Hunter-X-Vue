# UI 改造准备方案

状态：2026-10-16 用户已确认本方案；UI 已实现，业务回归与适配验收通过，见 [UI 验收记录](ui-validation.md)。B–E 阶段继续暂不推进。

## 目标与默认选择

采用用户参考图的蓝紫色主色、浅灰紫底色、白色大圆角卡片、简洁导航和适当留白，形成统一的猎头业务工作台。

- 默认浅色、纵向导航；中文和业务录入优先。
- 保留现有 Pure Admin 与 Element Plus，不更换框架，不增加 UI 库或全局依赖。
- 工作台采用卡片分区；人才库、职位库和公司资料保持表格及详情操作。
- 首页可使用现有 API 展示真实“最近更新的人才”和“在招职位”；不新增后端统计接口。
- 本次不涉及后端代码、schema、数据库数据、认证机制、`.env`、密钥、CI/CD、文件删除或公开发布。

### 列表与手机

- 列表：页面标题/新增操作 → 圆角白色内容区 → 搜索与数量 → 表格 → 分页。
- 手机：抽屉菜单 → 标题/操作换行 → 统计两列或单列 → 业务内容纵向排列；表格可局部横向滚动。
- 详情、编辑弹窗、下拉菜单和登录采用同一主题，避免首页更换后其他页面仍是旧风格。

## 实施顺序

1. **确认方案**：本文件与视觉规范由用户审阅。当前会话无主动切换 Plan Mode 的工具，使用可审阅文件承载方案，不声称已切换模式。
2. **外壳与主题**：统一颜色和控件；调整外框、侧栏、导航、滚动和默认布局，验证登录及导航。
3. **首页与业务页**：先完成工作台，再统一列表、详情、表单、附件和登录；真实数据与空状态一起检查。
4. **适配与回归**：覆盖桌面、平板、手机宽度和业务关键路径；对照原图逐项检查。
5. **交付**：提供实际截图、验证命令和已知限制。UI 验收不代表 B–E 功能已完成。

中间步骤用于控制改动顺序，不额外设置反复确认；方案确认后，可在本范围内连续完成并验证。

## 验收标准

### 视觉

- [x] 外层灰紫画布、蓝紫重点、白卡、大圆角和简洁侧栏形成一致风格。
- [x] 工作台、人才/职位/公司列表及详情、表单、登录均使用新主题。

- [x] 图表或数量有实际来源；空数据与错误状态不展示虚构业务结果。

### 适配与交互

- [x] 1440、1280、1024、768、390、360 px 宽度无整页横向溢出。
- [x] 侧栏收缩/展开和手机抽屉可用；滚动不让顶部、侧栏或主要操作相互遮挡。
- [x] 弹窗、下拉、日期选择和抽屉不被外框裁切；窄屏表单和底部操作可到达。
- [x] 姓名、公司、职位和多联系方式的长文本得到合理处理。
- [x] 焦点可见、键盘操作可用，允许浏览器缩放，并考虑减少动画偏好。
- [x] 对仍暴露的设置入口做兼容；不会保留点击后损坏页面的布局选项。

### 业务与工程

- [x] 原有登录、公司/职位/人才增改、沟通追加、职位关联、推荐状态、附件上传下载均通过。

- [x] `pnpm typecheck`、更新覆盖实际修改文件的只读 `pnpm lint:check`、`pnpm build` 通过。
- [x] 浏览器脚本使用已授权的隔离合成数据库，不向开发库加入演示数据；不触碰迁移或 schema。
- [x] 最终截图在加载/过渡结束后生成，放 `frontend/.artifacts/ui-<run-id>/`；保留旧产物，不自动删除。
