# 阶段 A：数据库与环境审阅

状态：用户已确认整体实施计划，并明确授权下列初始建表与迁移，先用 SQLite 本地开发及隔离测试库验证；PostgreSQL 在部署前另行实测。

## 环境检查

已发现 Node.js 24、pnpm 11、Git、Python 3.12；当前命令路径、常见安装目录和服务中未发现 PostgreSQL/Docker。不会自行安装全局工具或注册系统服务。

建议本阶段用项目内 SQLite 开发库 `var/hunter.db` 跑通个人工作台，SQLAlchemy 模型保持 PostgreSQL 兼容；正式部署仍按 PostgreSQL 方案准备。SQLite 验证不能证明 PostgreSQL 特性与并发正确性，部署前须在实际 PostgreSQL 验证。若用户选择 PostgreSQL，则等待可用的连接信息或另外授权安装方式，同时继续前端与接口工作。

## 首次 schema 范围

仅在全新的项目开发/测试数据库新增以下 10 张业务表和 Alembic 版本表；不连接、不覆盖既有业务数据库，不执行 downgrade/drop。

| 表 | 主要字段/约束 |
| --- | --- |
| users | UUID、唯一用户名、Argon2 密码摘要、名称、角色、启用状态、创建/更新时间 |
| auth_sessions | 用户外键、access/refresh 摘要、各自到期时间、撤销时间；不保存明文凭证 |
| companies | UUID、公司名、别名、行业、简介、版本与时间；允许同名，不按名称静默合并 |
| company_facts | 公司外键、内容、来源、来源链接、事实日期、录入时间 |
| candidates | 姓名、建联日期、当前公司外键及原始公司名、职位、JSON 联系方式、简历来源、JSON 附加值、版本与时间 |
| employments | 人才外键、公司引用/原名、职位、起止年月、是否在职、职责与业绩 |
| jobs | 公司外键、职位、非负或空团队人数、汇报上级、业务情况、JD、JSON 要求、状态、JSON 附加值、版本与时间 |
| applications | 人才和职位外键、推荐状态、时间；人才+职位唯一 |
| communications | 人才外键、可选推荐外键、沟通时间、渠道、内容、结果、下一步、跟进日期；推荐必须属于同一人才 |
| file_assets | 文件归属、原名、类型、大小、摘要、私有存储标识、解析状态、时间；基础阶段验证私有访问，解析在阶段 C |

共用约定：稳定 UUID、UTC 时间、日期单独存储、必要外键/索引。历史记录不级联删除。阶段 B–D 新增自定义字段定义、导入及 AI 任务表时另列具体迁移范围。

## 初始化和配置

- 拟创建一份只新增上述表的初始 Alembic 迁移，并在独立测试库验证升级和数据持久化。
- 获得授权后才执行 `alembic upgrade head` 初始化选定的全新本地开发库；服务启动不自动建表或迁移。
- 本阶段不创建/修改 `.env`、CI/CD 或 DeepSeek key；数据库连接可通过进程环境变量提供。
- 不提供固定演示账号。管理员由本地 CLI 通过隐藏密码输入创建；自动测试只用合成凭据和隔离测试库，不输出凭据。
- 应用登录正常生成短期访问令牌和 HttpOnly 刷新 Cookie；只存摘要，不新增持久化签名密钥配置。
- 用户原文件、Git 历史和全局软件不变；安装限前端项目依赖和后端 `.venv`。
