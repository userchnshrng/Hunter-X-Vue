## 用户能够完成的工作

1. 按简历来源、建联日期等条件筛选人才；按公司、状态筛选职位；清空条件后恢复完整列表。
2. 修改人才、岗位、任职经历、单条沟通和公司事实资料；保留记录创建时间与更新时间，继续支持追加沟通。
3. 给人才、职位添加文本、数字、日期、单选四类字段，例如期望地点、期望年薪、可到岗日期、意向状态；无需修改数据库表结构。
4. 下载人才导入模板，上传 `.xlsx` 或 UTF-8 CSV，选择工作表与表头，确认列对应关系，检查错误及重复，再提交。
5. 查看导入批次、逐行错误和已创建的人才；重复点击、网络重试和服务重启后重试同一批次，不重复生成记录。

沿用当前蓝紫 UI、登录和权限体系，不额外更换框架或引入新 UI 库。本阶段不实现 PDF/Word/图片解析、OCR、DeepSeek 或自动发送消息；这些继续归属 C、D。

## 一、日常维护

- 人才：关键词、简历来源、建联日期起止；原有多个联系方式保持可编辑。来源从现有记录中建议，并继续允许输入新来源，不增加固定字典表。
- 职位：关键词、公司、招聘状态；保留团队人数的空值与 0 区别、岗位编辑及暂停/关闭操作。
- 列表条件变化重置到第一页；非法日期区间由前后端同时提示，不返回容易误解的空结果。服务端过滤后再分页，不只过滤当前页。
- 任职经历、沟通、公司事实：逐条编辑，沿用现有字段限制、月份/时区/来源链接校验。沟通仍按时间线显示；未知沟通时间保持未知，录入时间单独显示。
- 本阶段不新增物理删除、人才合并、批量覆盖或部门/顾问私有库。公司事实仍由用户录入来源与资料日期，不自动联网生成。

## 二、自定义字段

适用实体仅人才和职位；公司字段扩展不在本阶段。

| 项目 | 规则 |
| --- | --- |
| 稳定标识 | 后端生成稳定 key，页面显示中文名称；实体类型、key 和值类型创建后固定 |
| 可维护项 | 中文名称、显示顺序、说明、必填/启用；单选项可追加、改显示名，稳定选项值不改 |
| 文本 | 长度有上限，空值与未填写清晰区分 |
| 数字 | 有限数值，拒绝布尔值、NaN 和 Infinity；0 为有效值 |
| 日期 | ISO 日期，UI 中文显示；不接受猜测式日期 |
| 单选 | 仅允许定义中存在的稳定选项值；不能随意塞入新字符串 |
| 必填 | 创建、导入及编辑保存时校验；历史记录不自动回填，缺值时提示补充，不捏造默认值 |
| 停用 | 从新录入界面隐藏，历史值继续可读、保存既有表单不丢值；不删除定义或历史内容 |
| 类型调整 | 不直接改变已建字段类型；需另建字段，数据转换另行评估 |

后端拒绝未知或不合法的新增自定义值；更新时保留未提交或已停用的历史值。前后端共用 API 定义渲染动态输入；不只在浏览器做校验。修改字段定义使既有导入预览失效时，提交前要求重新校验，避免按旧类型入库。

字段定义维护限定管理员；普通用户可查看定义并按定义录入。现有业务数据共享范围保持现状。

## 三、人才 Excel/CSV 导入

### 使用流程

人才库“导入人才”→上传→选择工作表/表头行→列映射→预览及校验→处理重复提醒→确认提交→结果与批次记录。

- 默认 `.xlsx`；CSV 接受 UTF-8/UTF-8 BOM。旧 `.xls`、`.xlsm` 不列为支持格式，明确提示另存为 `.xlsx`。
- Excel 可选择工作表和前 20 行中的表头行；CSV 单表。映射按列序号识别，允许重复/空表头名称，不因名称相同误选列。
- 建议起始限制：单文件 10 MB、单工作表扫描不超过 10,000 行、待导入非空行最多 5,000、最多 100 列；ZIP 展开总计不超过 50 MB、条目最多 1,000。界面提前告知，超限明确拒绝，不悄悄截断。
- 预览分页，只渲染当前页；服务端校验整个待提交集合。保留 Excel 原行号及原列标识，不用分页内编号冒充原行号。
- 用户可调整映射和修正预览中的值；原始值与更正值分别保留。有效行才可提交；非空缺姓名、非法日期等错误须先修正，不静默跳过。

### 七个基础字段

| 文件列 | 处理 |
| --- | --- |
| 建联日期 | Excel 日期或明确的 `YYYY-MM-DD` / `YYYY/MM/DD` / 中文年月日；空值允许，`03/04/2026` 等歧义格式报错 |
| 姓名 | 必填，允许重名；整行空白不导入，非空缺姓名定位到行 |
| 公司 | 保存原始当前公司名，不按同名自动关联/合并公司实体 |
| 职位 | 保存当前职位，允许空值 |
| 联系方式 | 可将多列分别映射为电话/微信/邮箱/其他；含混的合并内容按“其他”保留，不擅自拆错 |
| 沟通记录 | 与人才同事务创建一条历史沟通；实际沟通时间未提供时为空，不用导入时间替代 |
| 简历来源 | 原文保留；不自动归类为未知的来源平台 |

启用的自定义字段也可映射；必填和类型规则与手工录入一致。

数字形式的电话、科学计数法和可能丢失的前导零必须提示核对；已在原文件丢失的数字不能恢复。手机号/微信原值保留，重复判断只做明确规范化，不自动补国家代码或猜测身份。

### 公式、错误与重复

- 不执行公式、宏或外部链接。检测到公式单元格时保留位置并阻止该映射值直接提交，提示在源文件转换为普通值或手动修正；不把公式缓存或空值当作已核实结果。
- 单元格错误、损坏文件、合并表头/映射歧义、无有效数据均显示具体原因；不会标记“成功导入 0 条”来掩盖失败。
- 同批次及库内都检查姓名/联系方式重复。重名只作提醒，联系方式相同也由用户选择“跳过该重复行”或“仍然新建”；不自动覆盖或合并既有人才。
- 只允许新增；错误行须修正，重复行可显式跳过。提交前再次检查当前库，若预览后有人新增了重复联系方式，返回冲突并要求复核。
- 上传同一个文件的新批次会提示历史批次，但不直接阻止合理的再次上传。同一个批次重复提交必须返回原结果；幂等键和确认内容不一致时拒绝。
- 可下载包含原行号/字段/原因的 CSV 错误报告。导出用户原文时对公式起始字符做转义，不把文本导出成可执行公式。

### 提交一致性

批次记录版本、映射摘要和字段定义快照参与提交校验。服务端在一次事务中完成批次状态转换、全部人才/沟通创建和逐行结果回写；任何一行失败则整批回滚。

SQLite 使用明确的写事务/锁，PostgreSQL 设计使用行锁及唯一约束；并发请求不能各自读到可提交后重复插入。阶段 B 在 SQLite 上实际做并发/重试测试，PostgreSQL 不声称已验证。

未提交的预览可取消，状态和原件保留。服务重启后可查询历史及继续预览；不会因重启自动提交。批次原件与行数据只向创建该批次的账号开放，导入后人才继续按现有共享权限访问。
